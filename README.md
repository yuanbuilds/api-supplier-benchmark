# GLM 5.3 供应商自测

> 工具源码采用 [MIT License](LICENSE)；第三方依赖保留各自许可证，见 [第三方声明](THIRD_PARTY_NOTICES.md)。

这份入口用于供应商先自测、采购方再按同一标准复验。一次执行完成 **连通性 → 首 Token / 首正文计时 → 逐步升至 200 RPM**，结束后自动生成可读报告和一个回传 ZIP。

这是供本轮 **GLM 5.3** 使用的试行基准；覆盖更多模型的统一方案仍在完善，本轮先按这份方案测试和复验。

使用本仓库的测试包 **2.2.0**、EvalScope **1.13.0** 与固定测试配置。无需安装 Node 或 Promptfoo，按提示填写连接信息即可。测试工具通过不等于供应商的商业准入通过。

**回传 ZIP 不包含你的 API Key，也无需向我们提供 Key。** 结果只保留性能统计及复验所需证据，不保留上游原始回答；打包前自动检查认证 Key 残留，检测到即阻止生成 ZIP。

## 1. 准备并启动

需要能访问待测接口的机器，以及 Git、Bash、Python **3.10–3.12**（推荐 3.12）。已通过 macOS 真实接口测试，以及 Ubuntu 24.04 / Python 3.12 的安装、回归测试和 207 次本地模拟。Windows 请在 WSL2 中执行（尚未实机验证）；其他环境请先运行下文的本地演示确认安装。

```bash
git clone https://github.com/yuanbuilds/api-supplier-benchmark.git supplier-benchmark
cd supplier-benchmark
bash start_supplier_test.sh
```

入口会准备项目隔离环境并安装固定版本依赖；首次安装需要联网。随后按提示填写：

| 信息 | 怎么填 |
| --- | --- |
| 供应商名称 | 例如 `示例供方 A` |
| API 基础地址 | 例如 `https://api.example.com/v1`，不要附加 `/chat/completions` |
| 精确模型 ID | 填接口实际接受的名称。产品叫“GLM 5.3”不代表请求 ID 一定是 `glm-5.3`；请先在自己的模型列表中确认 |
| 测试机器地区 | 例如 `阿里云香港`，说明请求从哪里发出 |
| 思考模式 | 例如 `供应商默认开启思考`；须与实际接口配置一致 |

以上非敏感配置会保存到本机 `supplier.json`。**API Key 单独隐藏输入，不写入配置，不需要发给我们。** 也可由安全的运行环境提供 `SUPPLIER_API_KEY`；不要把真实 Key 写入 README、命令参数、提交记录或聊天消息。

入口先显示计划。确认接口支持本次测试、额度充足、测试窗口可用后，输入 **`RUN`** 执行。其他输入只保存配置，不调用模型。

## 2. 测试规模与口径

| 阶段 | 请求数 | 发起方式 |
| --- | ---: | --- |
| 连通性 | 1 | 单请求，检查完整流式正文 |
| 低负载计时 | 30 | 逐条请求，统计 P50 / P95 / P99 |
| 50 RPM 爬坡 | 25 | 固定发起间隔，约 30 秒 |
| 100 RPM 爬坡 | 50 | 固定发起间隔，约 30 秒 |
| 200 RPM | 600 | 每 0.3 秒计划发起一次，持续约 3 分钟 |
| **合计** | **706** | 不自动重试失败请求 |

每个请求的 `max_tokens` 默认为 **4096**。全部请求的输出上限合计 **2,891,776 Token**，并非预计实际消耗或费用；还需按接口实际口径考虑输入、思考和失败请求的计费。**3 分钟仅指 200 RPM 阶段**，全套总耗时还包含安装、预检、低负载计时、爬坡和在途请求完成时间。

这份 3 分钟计划用于首轮短时供给测试，不代表长期稳定性或持续供给 SLA 已通过。旧版 2.0.0 的 10 分钟报告保留原有口径，复验时请核对双方测试包版本与计划一致。

固定超时条件为：**每请求总超时 60 秒、连接超时 10 秒**。超过该条件记为 `TIMEOUT`，不自动重试或延长；思考较慢的模型也按同一条件记录。

三个口径请按报告理解：

- **连通成功**：HTTP 200、非空正文、`finish_reason=stop`、流结束标记 `[DONE]` 均满足。空回答、只有思考、`length` 截断、断流、429 和超时均不算完整成功。
- **首 Token（TTFT）**：从客户端开始 HTTP 调用，到收到首个非空思考内容或正文。**首正文（TTFOT）**单独计时，到首个非空回答正文。两者都包含连接池等待、DNS / TLS / 建连，排除发压调度等待；不能与排除建连的测试直接横比。分位数只统计完整成功请求，失败数单列。
- **本轮延迟目标：TTFT P50＜1 秒**。P50 是中位数，不是 P95 或平均值；等于 1 秒不达标。低负载计时和 200 RPM 阶段分别计算、分别标注是否达到要求，不合并样本；连通性单请求和爬坡阶段仅记录分布。这里的首 Token 可包含思考内容，不等于首正文。
- **200 RPM**：衡量固定窗口内的客户端发起频率，不等于 200 并发，也不等于 200 次成功。报告分别展示计划数、实际发起数、完成数、成功数、每分钟明细和调度滞后。窗口结束后等待在途请求完成。窗口从“请求已就绪、交给官方调度器之前”起算，包含交接开销，不会把起点移到首个成功请求；每分钟允许 1 次边界请求差异，并核对整个发起跨度。

负载是固定的中文短任务。报告记录实际模型 ID、机器地区、思考模式与输出上限；结论适用于这些条件，不代表任意上下文长度或输出长度都能达到相同结果。调用走直连网络，校验 HTTPS 证书，不跟随重定向；本次标准不继承系统代理。

本轮默认 `thresholds.ttft_p50_seconds=1.0`，严格按“小于”判定；新版入口读取旧配置而缺少此字段时，也会在执行计划中补上该有效门槛。成功率、P95 和首正文门槛暂未约定，保持 `null`，不会自行设定。**P50 分项达标不等于完整供给验收通过**：失败数、成功率和发压是否完成仍会单独显示；P50 未达标会明确标为未达到要求，P50 达标但未设成功率门槛时，总评仍保留为测量结果。若需调整门槛，请双方在测试前统一配置，不要跑完后再调整。历史报告仍按其原始配置解释。

思考开关等供应商特有参数可显式放入 `extra_body`，同时更新 `reasoning_mode` 说明；模型名、流式方式和输出上限使用入口提供的字段。

## 3. 查看与回传

运行结束后，终端会打印两条路径：**报告 `report.html`** 和 **回传 ZIP**。

1. 用 Chrome 打开本地 `report.html`，确认供应商、模型 ID、测试地区和思考模式正确。
2. **把终端最后打印的那一个 ZIP 原样回传。** 不必手工找文件、截屏拼报告或复制密钥。

ZIP 包含报告、机器可读摘要、全量请求时间和状态、经过字段筛选的 EvalScope 原生性能证据、版本/配置记录与文件校验值。回传包不包含 API Key 或上游原始回答；回传内容用于复验，勿公开发布。采购方使用相同版本和配置、从约定区域复测，并比较两次结果。

报告结论区分：

| 结论 | 含义 |
| --- | --- |
| `measurement_only` | 测量完成；可能已达到 P50 分项目标，但未约定成功率等完整验收门槛，不表示 SLA 已通过。部分失败会如实显示 |
| `passed` | 满足已经配置的测试阈值；不自动代表商业准入 |
| `not_passed` | 连通失败、某阶段没有成功请求、未达已设阈值，或发压条件未完成；具体原因见报告 |
| `incomplete` | 测试或证据不完整，不能据此判断供应商质量 |

阶段全失败或证据不完整时，入口停止后续加压并尽量保留报告。**失败也回传 ZIP**，并补充“机器地区、实际思考模式是否与配置一致”即可。若安装阶段尚未产生 ZIP，请回传终端最后一段错误和操作系统 / Python 版本；不要附带环境变量或 Key。

<details>
<summary>遇到失败时如何自查（先保留原报告）</summary>

| 表现 | 检查什么 |
| --- | --- |
| 安装失败 | Python 是否为 3.10–3.12，机器是否能访问 Python 包源；无需安装 Node |
| HTTP 401 / 403 / 404 | Key 权限、Base URL、精确模型 ID 与接口路径 |
| HTTP 402 | 查看网关/上游错误详情，核对两边余额或额度；网关账户有余额也可能是上游拒绝 |
| HTTP 429 | 核对请求、Token 和并发限制；保留错误率，不自行降压后声称达到 200 RPM |
| TRUNCATED / TIMEOUT | 检查 `finish_reason`、思考模式、4096 输出上限与 60 秒总超时；不要偷偷放宽条件 |
| 发压频率未达到 | 检查测试机网络和资源；不能只凭这一项归因于供应商 |

处理原因后如需重跑，使用同一约定配置并保留两次结果，不覆盖或删掉失败记录。

</details>

## 4. 常用命令

```bash
# 仅查看计划，不调用供应商
bash start_supplier_test.sh plan

# 读取已保存的 supplier.json；先展示计划，不执行
bash start_supplier_test.sh run

# 已确认测试窗口和额度，执行完整供应商测试
bash start_supplier_test.sh run --execute

# 本机模拟：不访问供应商、不消耗模型额度，约 1 分钟 200 RPM
bash start_supplier_test.sh demo

# 本机模拟也执行完整 706 次计划与 3 分钟 200 RPM
bash start_supplier_test.sh demo --full
```

`demo` 仅验证安装、调度与报告链路，报告会标注本地模拟，**不能作为 GLM 5.3 实测报告回传**。已有配置可通过 `--config 路径` 选择；不要修改代码中的测试规模或直接运行其他业务批次代替本标准。
